# 三语 Starter Kit 协作说明

这份文件是给团队成员看的三语接入说明。目标不是一次把全站全部翻完，而是先建立统一结构，让每个人后续做自己模块时，都能按同一套方式接入 `zh-CN`、`zh-HK`、`en`。

## 为什么现在就要定三语结构

如果每个人都先把文案直接写死在页面里，后面再统一补三语，会出现几个问题：

- 每个页面文案结构不一致，后面很难统一抽取。
- 同一个词可能被不同同事翻成不同版本。
- 有人用条件判断切语言，有人复制三份页面，后续维护成本会很高。
- 越晚处理，返工越多。

所以这次先用“联系我们 / 预约 Demo”这块做成完整示例，再让其他同事照这个结构接 FAQ、ROI、更新日志、术语词典等模块。

## 当前已经确定的三语规则

- 语言代码固定为：
  - `zh-CN`
  - `zh-HK`
  - `en`
- 路由结构固定为：
  - `/zh-CN`
  - `/zh-HK`
  - `/en`
- 根路径 `/` 默认跳转到 `/zh-HK`
- 当前先不做语言切换器 UI
- 第一阶段只完整接入你负责的首页底部联系与 Demo 模块

## 同事后续接入时的基本规则

1. 不要在 `JSX` 里直接写新的可见文案。
2. 所有标题、按钮、说明、字段名、placeholder、错误提示都放进统一字典。
3. 三个语言键都要补齐：
   - `zh-CN`
   - `zh-HK`
   - `en`
4. 页面只负责布局和逻辑，文案统一从 `locale + dictionary` 读取。

## 推荐的字典组织方式

建议按模块分组，不要把全站所有文案堆在一个平铺对象里。

当前建议至少有：

- `common`
- `homepage`
- `contactDemo`

后续同事可以继续补：

- `faq`
- `roiCalculator`
- `changelog`
- `glossary`

## 为什么“联系我们 / 预约 Demo”是示例模块

这个模块同时完成两件事：

1. 结构升级
   - 从原先单一 Demo 表单，改成：
   - `联系我们`
   - `预约 Demo`

2. 三语接入
   - 标题
   - 说明文案
   - 按钮
   - 字段名
   - placeholder
   - 错误提示
   - 成功 / 失败反馈

所以后续同事如果要接 FAQ、ROI 或别的模块，最简单就是照这个模块的组织方式做。

## 同事最需要记住的事

如果你正在做 FAQ、ROI、更新日志、术语词典或其他模块：

- 不要继续新增写死文案。
- 先看现有三语骨架和 `contactDemo` 的实现。
- 按同一套结构接入自己的模块。
- 如果已经写了一半，也尽量把新增文案集中整理，方便后面抽入字典。

## 不推荐的做法

- 在页面里直接写三套 `if / else` 文案。
- 为不同语言复制三份几乎一样的页面文件。
- 自己重新定义语言代码，比如 `zh`、`hk`、`cn`、`eng`。
- 只翻主标题，不翻按钮、报错、空状态、placeholder。

## 可以直接发给同事 AI 的一句话

```text
请先阅读 docs/I18N_STARTER_GUIDE.md 和 docs/I18N_AI_HANDOFF.md，再参考首页 contactDemo 的实现方式，把我负责的模块按同样结构接入 zh-CN、zh-HK、en，不要在 JSX 里直接写死文案。
```
