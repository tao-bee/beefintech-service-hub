# FAQ 自助查询功能方案

## 1. 功能目标

FAQ 自助查询用于帮助潜在客户、已合作客户和内部销售 / 实施同事快速获取常见问题答案，减少重复沟通，提升 BeeFintech Service Hub 的平台化服务感。

本功能属于第一阶段 P1 优先能力，目标是在不引入数据库的前提下，提供一个可演示、可维护、可扩展的静态 FAQ 页面。

## 2. 用户场景

- 潜在客户希望先了解产品接入方式、合作流程和数据安全边界，再决定是否预约演示。
- 已合作客户希望快速查看实施准备项、培训方式和售后支持说明。
- 销售 / 商务同事希望在演示沟通时快速定位问题答案，减少口头反复解释。
- 实施 / 交付同事希望统一常见答复口径，降低跨团队沟通成本。

## 3. 页面目标

- 让用户进入页面后快速理解 FAQ 的定位、适用场景和使用方式。
- 让首次访问用户可以先看热门问题，再使用搜索和分类筛选。
- 通过更完整的帮助中心结构提升可演示性和平台感。
- 支持折叠展开单个问题答案，并在需要时引导到人工咨询入口。
- 在无结果时提供清晰的空状态反馈和恢复建议。

## 4. 路由与文件范围

- 页面路由：`/faq`
- 方案文档：`docs/FAQ.md`
- 页面文件：`src/app/faq/page.tsx`
- 数据文件：`src/data/faq.ts`

如后续交互变复杂，可进一步拆分到 `src/components/faq/`。

## 5. 数据结构设计

第一阶段使用 TypeScript 常量维护 FAQ 数据，不引入数据库或 CMS。

建议结构：

```ts
type FaqCategory =
  | "all"
  | "integration"
  | "partnership"
  | "security"
  | "delivery"
  | "support";

type FaqItem = {
  id: string;
  question: string;
  answer: string;
  category: Exclude<FaqCategory, "all">;
  audience: string;
  keywords: string[];
};
```

说明：

- `id` 用于折叠项展开状态和后续锚点扩展。
- `keywords` 用于增强本地搜索命中率。
- `audience` 用于补充问题适用对象，增强扫读体验。
- `faqMeta.lastUpdated` 用于维护 FAQ 内容最近一次更新时间。

## 6. 分类设计

第一版 FAQ 使用以下分类：

- 全部问题
- 产品接入
- 保司合作
- 数据安全
- 实施交付
- 售后支持

分类需与 `docs/SPEC.md` 中描述保持一致，便于后续团队继续扩展内容。

## 7. 页面结构

### 7.1 顶部说明区

- 页面标题：`FAQ 自助查询`
- 品牌辅助标签：突出 BeeFintech FAQ Center 的帮助中心定位
- 简短说明：突出“接入、合作、安全、交付、售后”等问题沉淀范围
- 内容更新时间：按页面访问当天动态展示当前日期
- 快捷入口按钮：返回首页、预约演示
- 右侧深色信息面板：展示 FAQ 条目数、分类数量、使用方式和适合沉淀的内容类型

### 7.2 使用场景区

- 通过 3 张场景卡片说明 FAQ 适合哪些业务角色与沟通场景
- 帮助客户判断 LifeBee 是否适合自己的业务

### 7.3 新手引导区

- 提供“先看热门问题、再搜索筛选、找不到走人工咨询”的使用建议
- 让第一次使用 FAQ 的用户更快上手

### 7.4 热门问题区

- 展示 Top 10 热门问题
- 点击热门问题后，自动切换下方问答列表的分类与展开项
- 热门问题卡片应保持较紧凑的高度，避免列表过重

### 7.5 搜索与筛选区

- 关键词输入框
- 分类筛选按钮组
- 支持“全部问题”与各分类之间切换
- 查询结果区需要显示匹配数量和页面用途说明

### 7.6 FAQ 列表区

- 问题卡片列表
- 默认仅展示部分问题卡片，避免首次进入页面时一次性看到过多内容
- 支持“展开更多问题 / 收起问题”切换列表展示数量
- 单条问题支持展开 / 收起
- 展开后展示答案、适用对象、关键词标签、相关推荐问题和“是否解决问题”反馈区
- 展开按钮应只控制单条答案展开，不一次性展开全部内容

### 7.7 反馈与支持区

- 问题反馈与内容补充表单
- 问题反馈提交后，需要有明确的成功或失败提示
- 表单为空时，需要阻止提交并给出提示
- 人工咨询入口与人工处理说明
- 点击“提交人工咨询”后，应先提供明确的引导弹层，再跳转到人工咨询入口
- 反馈区采用单列全宽布局，不再与说明卡片并排

### 7.8 空状态区

- 当搜索无结果时，提示用户调整关键词或切换分类
- 提供一键返回“全部问题”的操作

## 8. 交互流程

### 8.1 搜索

- 用户输入关键词后，页面实时过滤结果
- 搜索范围包括：问题标题、答案正文、关键词标签、适用对象
- 搜索命中后，问题标题、答案正文和相关推荐问题中的关键词应高亮显示

### 8.2 分类筛选

- 用户点击某个分类后，只显示对应分类的问题
- 搜索和分类筛选可叠加使用

### 8.3 展开与收起

- 默认仅展开首条问题，降低初次进入的空白感
- 用户点击问题卡片后切换展开状态
- 第一版允许同时只展开一个问题，保持页面整洁
- 默认仅展示前几条问题，用户可手动展开更多问题，再收起回到精简视图
- 热门问题点击后，应自动切换到对应分类并展开目标问题

## 9. 异常与空状态

- 无搜索结果时显示“未找到匹配问题”的提示
- 空状态下提供“查看全部问题”按钮
- 第一版为静态数据页面，不涉及接口异常状态

## 10. 文案原则

- 中文界面优先
- 面向保险公司、经纪渠道、TPA、健康管理机构及内部交付同事
- 用词专业、克制、可信
- 未接入真实能力的内容使用“可支持”“通常会”“第一阶段以示例流程为主”等表述

## 11. 实施步骤

1. 新增 FAQ 功能方案文档，作为后续实现依据。
2. 在 `src/data/faq.ts` 中沉淀分类、问题数据和页面元信息。
3. 新增 `/faq` 页面，完成顶部信息区、热门问题区、搜索筛选区、问答列表区和反馈支持区。
4. 调整首页 FAQ 入口，使其直达新页面。
5. 运行 `npm run lint` 和 `npm run build` 验证。

## 12. 验收标准

- 存在独立 FAQ 页面路由 `/faq`
- 支持关键词搜索
- 支持分类筛选
- 支持问题答案展开 / 收起
- 无结果时有明确空状态提示
- 页面在桌面端和移动端均可正常浏览
- 首页存在进入 FAQ 页面入口
- `npm run lint` 通过
- `npm run build` 通过
