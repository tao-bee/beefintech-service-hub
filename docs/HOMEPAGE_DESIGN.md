# BeeFintech Service Hub 首页设计稿

## 1. 设计目标

首页要完成三件事：

- 让访客在 5 秒内理解 BeeFintech Service Hub 是保险科技服务中心。
- 把品牌宣传、服务能力和预约演示串成一个清晰转化路径。
- 明确露出 FAQ、ROI 计算器、更新日志、术语词典等增值服务入口，体现“服务平台”而不是普通官网。

## 2. 设计方向

整体风格建议：

> 专业、克制、可信、偏业务工具感。

不做夸张营销页，不做大面积渐变口号页。首页应该像一个保险科技服务工作台的入口：信息密度适中，层级清楚，客户能快速扫读和行动。

视觉关键词：

- 企业级
- 保险科技
- 数据流
- 服务中台
- 清晰可信
- 可持续运营

## 3. 首页结构

### 3.1 顶部导航

导航内容：

- 左侧：BeeFintech Service Hub 标识
- 中间：服务能力、客户场景、服务工具、更新日志、FAQ
- 右侧：预约演示按钮

交互要求：

- 点击导航可滚动到页面对应区块。
- 移动端收起为菜单按钮。
- 预约演示按钮始终明显。

### 3.2 首屏 Hero

首屏目标：

- 明确产品定位。
- 展示 BeeFintech 从官网到服务中心的升级。
- 引导用户预约演示或进入服务工具。

建议文案：

```text
BeeFintech 保险科技服务中心
连接保险业务、渠道运营与数字化交付的一站式服务平台
```

辅助文案：

```text
面向保险公司、经纪渠道、TPA 与健康管理机构，提供系统接入、渠道管理、保单服务、数据自动化和持续支持能力。
```

主操作：

- 预约演示

次操作：

- 查看服务工具

首屏右侧视觉：

- 使用“服务中台仪表盘”式界面预览，而不是抽象插画。
- 内容可包含：今日预约、FAQ 命中率、自动化节省时长、最近版本更新。
- 视觉上像真实产品界面，增强平台感。

首屏底部露出下一屏一部分，避免整屏只有口号。

### 3.3 核心能力区

标题：

```text
围绕保险数字化交付的核心能力
```

建议展示 4 个能力：

| 能力 | 说明 |
| --- | --- |
| 系统接入 | 对接保司、渠道、第三方服务系统，降低集成沟通成本 |
| 渠道运营 | 支持渠道协作、业务跟进和数据追踪 |
| 保单服务 | 支持保单处理、查询、变更和服务流程数字化 |
| 数据自动化 | 通过 OCR、RPA、规则引擎等能力提升处理效率 |

设计方式：

- 使用四列或两列能力卡片。
- 每个卡片包含图标、标题、短说明。
- 卡片不要太花，重点是可扫读。

### 3.4 客户场景区

标题：

```text
适配不同保险科技服务场景
```

建议展示 4 个场景：

- 保险公司数字化转型
- 经纪渠道运营管理
- TPA 服务协同
- 健康管理服务接入

每个场景展示：

- 场景名称
- 典型痛点
- BeeFintech 支持方式

示例：

```text
经纪渠道运营管理
痛点：渠道多、数据分散、业务跟进依赖人工。
支持方式：统一渠道数据、预约演示、FAQ 支持和运营指标看板。
```

### 3.5 服务工具入口区

这是首页的核心“平台化”证据。

标题：

```text
客户自助服务工具
```

展示 4 个入口：

| 工具 | 路由 | 价值 |
| --- | --- | --- |
| FAQ 自助查询 | `/faq` | 快速查询接入、合作、安全、交付和售后问题 |
| ROI 计算器 | `/roi-calculator` | 估算自动化带来的成本节省和效率提升 |
| 产品更新日志 | `/changelog` | 查看平台版本更新和服务变化 |
| 行业术语词典 | `/glossary` | 理解保险科技和系统集成常见概念 |

设计方式：

- 使用 2x2 工具入口网格。
- 每个入口包含图标、名称、说明、进入按钮。
- ROI 计算器可以做成更醒目的主工具卡片。

### 3.6 客户价值区

标题：

```text
让保险科技服务更快落地、更易运营
```

建议展示 4 个价值指标：

- 缩短系统接入周期
- 降低人工处理成本
- 提升客户问题自助解决率
- 增强服务过程透明度

说明：

- 如果没有真实数据，先用定性表达或“预计 / 可帮助”措辞。
- 避免写未经验证的绝对数字。

### 3.7 预约演示区

首页底部放预约演示表单，形成闭环。

表单字段：

- 姓名
- 公司
- 职位
- 联系方式
- 需求类型
- 补充说明

旁边展示提示信息：

```text
提交后，我们会根据你的业务场景安排产品演示或接入咨询。
```

需求类型：

- 产品演示
- 系统接入咨询
- 渠道合作
- 数据安全 / 合规咨询
- 售后支持
- 其他

## 5. 视觉规范建议

颜色：

- 主背景：浅灰白或冷白
- 主文字：深墨蓝 / 近黑
- 主色：BeeFintech 品牌蓝
- 强调色：青绿色或琥珀色，用于状态、指标和关键按钮

字体：

- 中文优先使用系统默认无衬线字体，保证跨设备可读。
- 标题字重略高，正文保持克制。

组件风格：

- 圆角控制在 8px 左右。
- 卡片边框轻，阴影弱。
- 按钮需要有清晰 hover 和 focus 状态。
- 图标优先使用 lucide-react。

动效：

- 首屏模块可做轻微进入动画。
- 卡片 hover 只做轻微上浮或边框变化。
- 不做过度炫技动画，保持企业级可信感。

## 6. 移动端适配

移动端优先保证可读和可操作：

- 顶部导航折叠为菜单。
- Hero 改为单列布局，视觉预览放在文案下方。
- 能力、场景、工具入口全部单列排列。
- 表单字段宽度占满。
- 按钮高度不低于 44px。

## 7. 首页验收标准

- 首屏能明确看到 BeeFintech Service Hub 的定位。
- 首页包含预约演示入口和服务工具入口。
- 至少展示核心能力、客户场景、客户价值三个品牌宣传模块。
- 预约演示表单字段与需求文档一致。
- 桌面端和移动端布局都不出现文字溢出或元素重叠。
- 首页风格偏企业服务平台，不能像普通营销模板。
