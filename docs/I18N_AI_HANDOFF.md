# 三语接入 AI 交接说明

这份文件是给后续 Codex / AI coding agent 直接执行的接入规范，不是概念介绍。

## 任务目标

为 BeeFintech Service Hub 接入统一的三语结构，语言版本固定为：

- `zh-CN`
- `zh-HK`
- `en`

路由结构固定为：

- `/zh-CN`
- `/zh-HK`
- `/en`

根路径 `/` 默认跳转到：

- `/zh-HK`

## 当前阶段范围

第一阶段不是全站完整三语，而是：

1. 先建立统一三语骨架。
2. 先把首页底部“联系我们 / 预约 Demo”做成完整示例模块。
3. 首页其他区域允许暂时保留原语言。
4. 其他模块后续再渐进接入。

## 强制规则

1. 不要在 `JSX / TSX` 里新增写死的业务文案。
2. 不要在组件里写散落的 `if (locale === ...)` 文案分支。
3. 不要为三种语言复制三份几乎相同的页面。
4. 不要自定义新的语言代码。
5. 所有标题、说明、按钮、字段名、placeholder、错误提示、成功提示都必须走统一字典。
6. 新模块至少补齐：
   - `zh-CN`
   - `zh-HK`
   - `en`

## 推荐实现方式

- 页面和组件负责：
  - 布局
  - 交互
  - 提交逻辑
- 字典负责：
  - 标题
  - 文案
  - 标签
  - placeholder
  - 错误提示
  - 成功 / 失败反馈

统一原则：

- 页面通过 `locale + dictionary` 读取文案。
- 语言判断集中在 `src/lib/i18n.ts` 和路由层。
- 页面本身不承担翻译判断职责。

## 当前示例模块

当前请优先参考：

- `src/lib/i18n.ts`
- `src/app/[locale]/page.tsx`
- `src/app/[locale]/contact-demo-section.tsx`

这三个文件展示了：

- 多语言路由入口
- 字典读取方式
- 联系方式优先的版块结构
- 仅 `contact` 必填的表单行为
- 成功 / 失败 / 提交中反馈

## 新模块接入步骤

1. 先检查现有三语路由和字典结构。
2. 在字典里增加你负责模块的三语文案。
3. 把页面里写死的业务文案替换成字典读取。
4. 确认 `zh-CN`、`zh-HK`、`en` 都能正常显示。
5. 确认按钮、报错、空状态、placeholder 没有漏翻。
6. 跑 `lint` 和 `build` 验证。

## 验收标准

当你说“这个模块已接入三语”时，至少要满足：

1. 模块在 `zh-CN`、`zh-HK`、`en` 下都可访问。
2. 模块所有可见业务文案都走字典。
3. 页面中没有新增写死的业务文案。
4. 错误提示和空状态也完成三语化。
5. 不破坏现有路由结构。
6. `lint` 通过。
7. `build` 通过。
