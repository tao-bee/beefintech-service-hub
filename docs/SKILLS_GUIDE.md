# Codex Skills 使用说明

本文说明本项目推荐使用的两个 Codex skill：`superpowers` 和 `frontend-design`。团队成员不需要理解 skill 的内部实现，只需要知道什么时候该让 AI 使用它，以及如何提出清楚的请求。

## 为什么要使用 skills

Skill 可以理解为给 AI 增加的一套专项工作方法。

- `superpowers`：帮助 AI 更有条理地完成复杂任务，比如需求拆解、计划制定、执行检查、复盘总结。
- `frontend-design`：帮助 AI 更专业地完成前端页面和组件设计，避免页面像临时拼出来的模板。

建议团队成员在开始开发前先阅读 README 中的“AI 协作技能安装”章节，并确认两个 skill 都已经安装。

## 使用总原则

- 不要只说“帮我做一下”，要说明目标、范围和验收标准。
- 复杂任务先让 AI 分析和计划，再让 AI 修改文件。
- 前端页面、组件、交互和视觉优化任务，优先点名 `frontend-design`。
- 需求拆解、执行规划、测试记录、复盘总结和多人协作流程，优先点名 `superpowers`。
- 每次让 AI 修改代码或文档后，都要求它说明改了哪些文件、如何验证、还有什么风险。

## superpowers

### 适合使用的场景

`superpowers` 更适合用在“任务还比较复杂，需要先想清楚”的场景，例如：

- 拆解比赛需求和评分点
- 制定开发计划和任务顺序
- 梳理某个功能的实现步骤
- 检查当前项目还有哪些缺口
- 记录 AI 协作过程和 Prompt
- 整理测试说明和复盘总结
- 遇到问题时分析原因和修复路线
- 合并分支前检查改动范围和风险

### 不适合使用的场景

以下场景不一定需要特意点名 `superpowers`：

- 只改一个错别字
- 只查看一个文件内容
- 只执行简单 Git 命令
- 只问某个很明确的小问题

### 推荐提示词

理解项目时：

```text
请使用 superpowers 的方式阅读 README.md 和 docs/SPEC.md，先不要写代码。请总结项目目标、交付清单、当前缺口、优先级和下一步建议。
```

拆解功能时：

```text
请使用 superpowers 帮我拆解 FAQ 自助查询功能。要求输出页面结构、数据结构、交互流程、接口需求、验收标准和建议开发顺序。先不要写代码。
```

开始开发前：

```text
请使用 superpowers 检查当前 Git 状态和项目结构，然后为本次任务制定一个简短执行计划。确认范围后再开始修改文件。
```

开发完成后：

```text
请使用 superpowers 复盘本次改动，说明改了哪些文件、实现了什么、如何验证、是否有遗留风险，以及建议提交信息。
```

写比赛文档时：

```text
请使用 superpowers 根据当前项目内容生成 AI 协作记录，要求包含目标、使用的 Prompt、AI 输出、人工调整、验证结果和踩坑记录。
```

## frontend-design

### 适合使用的场景

`frontend-design` 更适合用在所有和前端体验有关的任务，例如：

- 设计或改造首页
- 设计 FAQ、ROI 计算器、更新日志、术语词典页面
- 优化页面布局、配色、字体层级和按钮状态
- 设计表单、筛选器、卡片、工具栏等组件
- 修复移动端排版问题
- 让页面更适合演示和比赛展示

### 不适合使用的场景

以下场景不一定需要特意点名 `frontend-design`：

- 只写后端 API
- 只改 Markdown 文档
- 只处理 Git 合并
- 只修复纯 TypeScript 类型错误且不涉及 UI

### 推荐提示词

设计新页面时：

```text
请使用 frontend-design 设计并实现 ROI 计算器页面。目标用户是保险科技客户，页面需要专业、清晰、适合演示。请先说明设计方向，再修改代码，并确保移动端可用。
```

优化已有页面时：

```text
请使用 frontend-design 优化首页视觉和信息层级。要求保持 BeeFintech 的保险科技业务定位，不要做成营销模板页。完成后说明改动文件和验证方式。
```

做组件时：

```text
请使用 frontend-design 实现一个 FAQ 搜索和分类筛选组件。要求交互清楚、状态完整、移动端不拥挤，并使用项目现有的 Tailwind CSS 风格。
```

修复页面问题时：

```text
请使用 frontend-design 检查当前页面在移动端的布局问题，修复文字溢出、按钮拥挤和卡片间距问题。完成后说明你检查了哪些视口。
```

## 两个 skill 如何配合使用

复杂功能建议这样安排：

1. 先用 `superpowers` 拆解需求和执行顺序。
2. 再用 `frontend-design` 设计页面和交互。
3. 实现后让 AI 运行检查或构建。
4. 最后用 `superpowers` 总结改动、验证结果和协作记录。

示例：

```text
请先使用 superpowers 拆解行业术语词典功能，输出页面结构、数据结构和验收标准。确认后，再使用 frontend-design 设计并实现页面。
```

## 团队协作建议

- 提需求时尽量说清楚用户是谁、页面解决什么问题、完成后怎么验收。
- 让 AI 修改前，先要求它检查当前分支和工作区状态。
- 一个功能一个 `feature/xxx` 分支，不要直接在 `dev` 或 `main` 上开发。
- 让 AI 输出改动说明时，要求包含文件路径，方便其他成员 review。
- 前端页面完成后，至少运行 `npm run build`；如果有交互表单，也要在浏览器里试一遍。
- 文档类任务完成后，不一定需要构建，但要检查 Markdown 标题、链接和命令是否清楚。

## 常用组合提示词

新功能从 0 到 1：

```text
请使用 superpowers 和 frontend-design 协助完成一个新功能。先拆解需求和验收标准，再设计页面和交互，然后实现代码。每一步开始前先说明计划，完成后说明改动文件和验证结果。
```

页面质量检查：

```text
请使用 frontend-design 检查当前页面是否适合保险科技服务平台展示，重点看信息层级、视觉一致性、移动端布局、按钮和表单状态。先给问题清单，再修复。
```

开发后复盘：

```text
请使用 superpowers 对本次开发进行复盘，输出：任务目标、关键 Prompt、改动文件、验证结果、遇到的问题、下次可以改进的地方。
```

## 验收清单

使用 `superpowers` 后，至少应该得到：

- 明确的任务目标
- 可执行的步骤
- 风险或注意事项
- 验证方式
- 后续建议

使用 `frontend-design` 后，至少应该检查：

- 页面是否符合保险科技服务平台定位
- 信息层级是否清楚
- 移动端是否可用
- 交互状态是否完整
- 按钮、表单、卡片等元素是否统一
- 是否通过构建或基本浏览器验证

## 一句话记忆

- 想清楚怎么做，用 `superpowers`。
- 把页面做专业，用 `frontend-design`。
